# Release 1 Daily-Use Beta Validation Guide

This is an executable acceptance guide for the later implementation. It does not authorize or supply code/tasks.

## E01 — Blocking preconditions

1. Verify the retained compatibility spike hashes/log and exact pins in `plan.md`; rerun after any pin/lock change. This limited gate is PASS in retained evidence, but does not imply Plan Gate or runtime acceptance.
2. Deploy the exact immutable build behind TLS with PostgreSQL/object storage, three fixed roles, Arabic/English, and acceptance masters.
3. Record build/lock digest, environment, UTC window, browser versions, database/object backup IDs, and test identities.
4. Validate `contracts/openapi.yaml` as OpenAPI 3.1 and resolve every local `$ref`; fail on warning/error.

## E02 — Contract and deferred-surface rejection

- Exercise every operationId at least once with an allowed role and once with a denied/invalid condition; verify RFC 9457.
- Verify mutations require `Idempotency-Key`; existing-aggregate mutations require `If-Match`.
- Crawl API paths and UI routes/build manifests. Fail if any endpoint or interactive control exists for: bank import/matching, tax pack, historical migration, multi-source allocation, shared-expense allocation, approval designer, route designer, or advanced claim settlement.
- Probe representative forbidden paths such as `/bank-imports`, `/tax-packs`, `/migration-records`, `/source-allocations`, `/expense-allocations`, `/approval-policies`, and `/route-templates`; expect 404 and no schema/navigation discovery.

## Numbered full daily-use beta scenario

**E03.** Sign in as each fixed role; prove permission shaping and self-approval denial, then call `signOutCurrentSession` successfully as Owner/Admin, Operations, and Finance/Viewer and prove the terminated session cannot be reused. Create essential masters. Seed each fixed approval action and call `listFixedApprovalInbox`; schema-validate every `ApprovalInboxItem` and render the dialog directly from its required exact subject type/ID/reference/version/hash, changed-field before/after diff, evidence metadata/source links, conflicts, requester identity/time, required role, decision context, approval state/version. Fail if the response is a generic entity page, any controlled field requires an untyped refetch, or self-approval can be submitted. Run the same critical workflow in English LTR and Arabic RTL.
**E04.** Operations creates Project A plus a 100 MT sales contract with omitted tolerances and adds two purchase contracts; Owner/Admin approves exact versions. Create Project B for a second independent sales contract; amend Project A instead of creating another Project for a same-contract change.
**E05.** Create two supplier shipments with every strict supplier field, including required `containerNumbers` and `sealNumbers`; call `getSupplierShipmentWorkspace` and `listSupplierShipmentDatasetHistory`; assert aggregate `reference` exists on each workspace but is absent from every active/history dataset, and assert every dataset requires `shipmentId`, `invalidatedApprovalIds`, and all non-optional authoritative fields; submit exact datasets, approve with different Owner/Admin, confirm, mark `IN_TRANSIT`, then `RECEIVED`. Create 20/40/40 MT sales shipments with product/coffee, bags/weight, all locations, incoterm, containers/seals and transport; call `getSalesShipmentWorkspace` and `listSalesShipmentDatasetHistory`; assign exactly one confirmed source each, submit and obtain different Owner/Admin approval for each exact dataset/source binding, confirm, mark `IN_TRANSIT`, then `DELIVERED`. Exercise reasoned eligible `CANCELLED` and `REJECTED` examples on disposable shipments. Verify every command has version/idempotency/audit and prove a second-source field/endpoint does not exist.
**E06.** Attempt outside-tolerance confirmation without approval; inspect detailed blocker. Request Owner/Admin exception for the exact dataset/reason, approve, and confirm. Revise both a supplier and sales dataset while eligible using strict dataset-facts-only payloads plus `changeReason`/optional evidence: preserve old revision, expire approval/exception, reset confirmation, reject stale `If-Match`, and require submit/approve/confirm again. Attempt to inject `reference`, `shipmentId`, Project/contract IDs, primary source, supplier linkage, and unknown fields into each revision payload; each must fail schema validation and aggregate identity must remain unchanged. Prove revision after `IN_TRANSIT` is rejected.
**E07.** For each fixed route, complete the required milestone/evidence checklist; upload, call `getEvidenceMetadata`, view, download, and schema-validate explicit verification state/time/actor and returned immutable SHA-256/size/media-type/source linkage against bytes. Assert a `PENDING` response contains JSON-null `verifiedAt`/`verifiedBy`; after `VERIFIED`, assert both are required non-null and identify the verification instant/actor; reject a fabricated `VERIFIED` payload missing either field. Leave one required item incomplete and prove final closure blocks. Prove there is no route-template editor.
**E08.** Generate CINV and Packing List from the same exact dataset in English, Arabic, and bilingual modes; poll status to Ready and compare shared fields. Approve an exact output; revise it and prove old bytes/hash remain. Cancel a draft/new revision with reason.
**E09.** Build an outbound manifest with channel, ordered To/Cc, exact output ID/version/hash, attachment IDs/versions/exact filenames/byte sizes/hashes, exact subject, and exact body bytes/media type/byte size/hash. Approve it. Separately revise recipient, attachment name/bytes, subject, body bytes, and output version; each creates a new manifest and makes old approval unusable. Reapprove, retrieve exact preview, explicitly send without a caller body, and byte-compare approved versus transport-captured body/attachments. Force missing object/hash mismatch/provider failure; each must fail closed and append immutable attempt/result/audit. Retry appends a new attempt. Prove no automatic send.
**E10.** Confirm a supplier invoice against one supplier shipment. Prove an unallocated confirmed invoice can be reasoned-cancelled by Owner/Admin, an allocated invoice cannot be cancelled until allocations reverse, and a replacement confirmed invoice restores the closure prerequisite. Record a USD 30,000 customer advance before CINV, allocate USD 20,000 and USD 10,000 across CINV targets; record supplier advance/payment and allocate to supplier invoice. Attempt over-allocation, wrong party/currency, stale version, replay, reversal, and refund. Reverse one allocation explicitly; verify immutable original plus compensating row, exact movement availability/document outstanding/statement balances, shipment and Project financial reopening, and idempotent replay with no second reversal.
**E11.** Record shipment freight and Project customs expenses, each directly scoped with proof. Approve exact versions. Correct one approved expense through exact cancellation/replacement submission, different Owner/Admin approval, and apply; verify old/new evidence remains immutable, direct edit/delete is absent, margin/statement/closure recompute, and replay is harmless. Prove neither multi-shipment/shared allocation nor allocation method is present.
**E12.** Reconcile customer, supplier, sales-shipment, supplier-shipment, and Project statements by currency. Verify expected, committed, actual operational margin, and cash position formulas/source drill-down. Advances change cash only; AED conversions disclose rate/date/source.
**E13.** Open two simple claims and move each under review. Attempt direct terminal transition and apply without approval; both fail. Submit exact proposed `RESOLVED` and `REJECTED` outcomes with reason/evidence; prove requester self-approval fails, Owner/Admin rejection leaves claim under review, dataset/version change expires applicability, and only approved apply reaches the proposed terminal state with audit. Prove open/under-review claim blocks final close and no discount/replacement/compensation/netting automation exists.
**E14.** Prove zero invoice is not enough: a shipment without an approved non-cancelled CINV stays Open. Fully collect one shipment while document/claim items remain; it must become Financially Closed. Fully collect all shipments; Project becomes Financially Closed. Verify the assessment lists every remaining quantity/delivery/route/document/supplier/expense/claim/approval blocker. Approve one eligible named exception, prove it cannot cover another/version, clear all blockers, submit/approve/apply final close, then exercise each invalidator (allocation reversal/refund, document revision/cancel, approved-expense correction, new claim, eligible shipment cancel/reject) on controlled fixtures and verify stale assessment/exception invalidation plus Final Close reopening. Submit/approve/apply explicit reopen with reason and recomputed financial state.

Expected throughout: zero unexplained quantity/money/statement variance; no lost update; immutable approved evidence; stable references; complete actor/time/version/reason audit.

## E16 — Security, audit, performance, and recovery

- Test MFA for Owner/Admin; assert Secure/HttpOnly/SameSite=Strict/Path=//no-Domain cookie flags, 30-minute idle and 12-hour absolute expiry, token rotation, required CSRF on every authenticated mutation, and allow-listed Origin/Referer fail-closed behavior. Call `listPilotUsers` and `listPilotUserSessions`; assert sign-in and listed-session responses expose the exact session `version` needed by `If-Match`, and active rows carry explicit null `revokedAt`/`revokedBy`/`revocationReason`. Revoke an exact non-current session; schema-validate the response and refreshed list row as `revoked=true` with required non-null revocation time, actor snapshot, and reason, then assert denied reuse. Reject any revoked response missing one; then test authorization/IDOR, upload abuse, rate limiting, log redaction, audited downloads/sends, TLS and encryption. Require zero unaccepted Critical scan findings.
- Replay same idempotency key/payload (same outcome, no duplicate), then changed payload (`IDEMPOTENCY_KEY_REUSED`). Submit stale `If-Match` (`STALE_VERSION`). Call `listProjectAuditEvents`; assert ascending sequence and all enumerated hash-payload fields. Independently construct the exact object `{id, projectId, sequenceNo, actor, sessionId, action, aggregateType, aggregateId, aggregateVersion, beforeHash, afterHash, previousEventHash, occurredAt, reason, correlationId, idempotencyKey}` with every key present and absent optional values encoded as JSON null; compute `lowercase-hex(SHA-256(UTF-8(RFC8785-JCS(payload))))` and match every `eventHash`. Assert genesis `previousEventHash` is JSON null, every later value equals the prior event hash, and `pageStartPreviousEventHash`/`pageEndEventHash` preserve continuity across every cursor page; then verify the retained daily head; application role cannot update/delete audit or approved bytes.
- At 50 sessions require p95 reads <=500 ms, mutations <=800 ms; document accept <=2 s and render <=30 s. Concurrent settlement/tolerance/closure commands preserve all invariants.
- Perform an isolated pre-beta PITR/object restore from the separate encrypted copy. RPO <=15 minutes, RTO <=4 hours, with zero missing sampled Project/version/allocation/approval/audit/hash/object link.

## E17 — Milestone evidence and exit

- **2026-11-12**: deployment URL/build, full scenario result, restore report, and first real daily-use entry.
- **2026-11-12–18**: daily observation/correction log with severity, affected journey, fix build, regression evidence, and unresolved risk.
- **2026-11-19**: frozen stabilized build, full rerun, bilingual/visual evidence, reconciliation, security/restore evidence, and Owner acceptance.

The pilot passes only when all active acceptance above passes and deferred surfaces are absent. It remains blocked if the compatibility spike lacks clean install/typecheck evidence or the independent Plan Gate is not accepted.
